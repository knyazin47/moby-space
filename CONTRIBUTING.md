# Разработка Moby Space

Командный прототип Space Hackathon с МТБанком. Оба режима — локальная реплика
и семейный клиент Go/SQLite — работают только с синтетическими данными.

## Навигация

- [Архитектура](docs/architecture.md), [стек](docs/stack.md).
- [Клиент](frontend/README.md), [сервер](backend/README.md), [API](docs/api/README.md).
- [Проверки](docs/development/testing.md), [сборки](docs/development/releases.md).
- [Продукт](docs/product/README.md), [ресурсы и лицензии](tools/assets/README.md).

Делайте небольшие изменения с понятной целью. Перед началом обновите `main`
через `git pull --ff-only`. Для совместной работы согласуйте владельца общих
файлов; в pull request опишите поведение и проверки. Общую историю без
согласования не переписывайте. Изменение одного режима не должно ломать другой.

Используйте закреплённые SDK и lockfiles. Обновление зависимостей оформляйте
отдельно с проверкой Android/iOS. Для protobuf сохраняйте номера полей,
presence/false/zero и воспроизводимую генерацию. Документацию обновляйте вместе
с поведением; источники mutable content перечислены в [реестре](docs/ADMIN_CONFIGURABILITY.md).

В Git не должны попадать реальные профили, номера карт, банковские APK,
декомпилированный код, `.env`, базы, токены, ключи или материалы без условий
распространения. Для тестов нужны явно synthetic fixtures. Ресурсам нужны
источник, лицензия и необходимые уведомления.

Авторство соответствует выполненной работе. Совместные изменения допускают
`Co-authored-by` с согласованным именем и GitHub email. Сборка релиза не
означает проверку на физическом телефоне.

## Подтверждение участия

Участники команды могут подтвердить своё участие отдельным PR с изменением
только [AUTHORS.md](AUTHORS.md):

1. Сделайте fork репозитория и создайте в нём ветку для своего подтверждения.
2. В своей строке замените `[ ]` на `[x]`. Можно добавить короткий комментарий
   о своём участии. Строки других участников оставьте как есть.
3. Создайте коммит со своим именем и email, привязанным к вашему GitHub-аккаунту.
   Подойдёт GitHub `noreply` email; публиковать личный email в `AUTHORS.md` не нужно.
4. Откройте pull request в `main` общего репозитория.

Мейнтейнер проверяет подтверждение и принимает PR через `Create a merge commit`,
сохраняя непустой авторский коммит участника. Для учёта в
[Contributors](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-a-projects-contributors)
коммит должен попасть в default branch, а его email — быть связан с аккаунтом
автора. Граф показывает до 100 участников и может обновляться с задержкой;
merge commit сам по себе не заменяет коммит участника. Подтверждение в AUTHORS
относится к участию в проекте и не распределяет авторство исторического кода.
